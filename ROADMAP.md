# Roadmap: feature gaps vs Adobe Premiere Pro

How the app compares with a desktop NLE today, and what is still missing. Two
questions, two sections: what has shipped (so a closed gap is not listed twice)
and what remains, grouped by how often a working editor would feel it.

Research date: September 2026 (Premiere 26.x). The gap table below is a historical snapshot last
re-verified against the code on 2026-10-18 at 0.8.6. The 0.8.7, 0.8.8, 0.8.9, 0.9.0, 0.9.1, 0.9.2,
0.10.0, 0.10.1, 0.10.2, 0.10.3 and 0.11.0 rows below record later releases: the playhead fix, the
motion-blur static-window bypass, VTT export, the battery speedup, the Sequence Settings dialog plus
menu fixes, the ripple preloader, the appearance palettes, the ten added palettes, the fullscreen
control, the toolbar tooltip placement fix, and the public launch. None of them closes a Premiere gap,
so no status changed for any of them. A gap moves to "Shipped" only once the release that closed it is recorded in
[CHANGELOG.md](CHANGELOG.md).

The editing core is not tracked as a gap: the multi-track timeline, trim / split
/ razor, A/V linking, ripple delete, cross-dissolves, text overlays, gain / mute,
undo and project save / load all exist today.

## What remains

**Tier 1 is complete.** The 0.7.0 bundle closed its last open cells (3D
`.cube` LUT import, the waveform and vectorscope scopes, and frame blending in
both render paths), and the table below records how each of the five original
gaps closed: four shipped, two cells closed as recorded non-goals. Open cells:
none. **Tier 2 is complete:** 0.8.0 shipped bounded export memory (the streamed
`Export to file` path) and proxies (a session lower-resolution preview stand-in),
and 0.8.1 shipped nested sequences / compound clips. Tier 3 is complete:
0.8.2 shipped dip to black, the first of the four transition items,
0.8.3 shipped title presets, and 0.8.4 shipped wipe, slide and push,
0.8.5 shipped subtitles / captions (SRT import and export),
and 0.8.6 shipped effects beyond opacity.

### Tier 3: content and polish

- **More transitions: wipe, slide, push (shipped at 0.8.4; dip-to-black shipped at 0.8.2).** The span model in
  `transition.ts` already computes the overlap, and a shared `transitionGeometry` helper now carries
  the spatial parameter (a clip region for wipes, picture offsets for slide and push, with a feathered
  wipe edge blending the pair), so monitor and export render all five types from the same numbers.
- **Effects beyond opacity (shipped at 0.8.6):** an ordered per-clip effect stack (crop with
  feather and zoom refill, sixteen canvas blend modes as a fixed field under Opacity, an eyedropper
  chroma keyer with despill, track mattes by id with luma/alpha modes, motion blur accumulating
  clip-local Motion up to 8 samples) plus a track visibility eyeball on video/text lanes. The exotic
  blend remainder (Dissolve, Divide, Subtract, Vivid/Linear/Pin Light, Hard Mix) is a recorded
  non-goal: no canvas primitive exists for it.
- **Subtitles / captions (shipped at 0.8.5, VTT at 0.8.9):** a caption flag on text clips
  plus SRT import and export. Import stamps timed cues on a first-free
  Captions track, a Captions panel beside the timeline edits them with
  click-to-seek, and export writes them back in start order as SRT or WebVTT.
- **Title presets (shipped at 0.8.3):** save and reuse styled text
  (Essential Graphics style). A project-level `textPresets` library with
  four built-ins, applied from the Inspector or the Add Text picker.

## Deliberately not planned

- **Studio-scale workflows:** multicam editing, tape-style media management,
  productions / shared projects, hardware I/O. Not relevant to this product's lane.
- **Frame-accurate seeking of arbitrary codecs:** `<video>` cannot provide it. The
  WebCodecs exporter is what made export frame-exact, and the preview stays a
  stepped approximation for reversed and ramped clips.
- **ProRes export.** The muxer is not the limitation: mediabunny already carries
  ProRes fourCC profiles, and it gates every encode on `canEncodeVideo`, the same
  probe `export/mp4.ts` already uses for its audio codec. The encoder is: no
  shipping browser exposes a ProRes `VideoEncoder`. Per mediabunny's compatibility
  guide (<https://mediabunny.dev/guide/supported-formats-and-codecs>, checked
  2026-10-07), "ProRes is not supported by WebCodecs": decoding needs the
  `@mediabunny/prores` extension and encoding exists only server-side in
  `@mediabunny/server`. A shipped export path would be a promise the platform
  cannot keep.
- **HEVC export.** This one is a value call, not a platform claim. An encoder
  exists and `canEncodeVideo('hevc')` would gate an option safely, so the codec is
  reachable. It is not planned because H.264 at the shipped bitrates already covers
  the upload path, and the cost is real: a probe, a dialog option, and per-project
  even-dimension gating, since HEVC requires even dimensions while the project
  limits clamp only to 64..3840 by 64..2160. An option that appears and then fails
  the export is the platform promise this section exists to avoid.
- **Spectral or learned noise reduction** beyond the fixed broadband chain.
  "Learned" needs a model path (hosted inference, or shipped weights plus a runtime), and this repo
  has none; a credible model would also add bundle size and runtime cost. "Spectral" is possible but
  not verifiable to this repo's own standard:
  the fixed chain is vindicated by a measured frequency-response test that runs in
  plain Node, and a spectral gate inside an `AudioWorklet` is browser-only, so the
  exact thing being changed would leave the Node-testable state core. A tunable
  broadband chain is a different item: the open cell asked for work beyond the
  fixed chain, so adjustable strengths would leave it just as open.
