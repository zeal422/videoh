## Layers and data flow

Four layers with a single direction of mutation:

```text
UI components ──EditorCommand──▶ store.apply() ──▶ applyCommand() ──▶ new Doc
     ▲                                                                 │
     │                                                                 ▼
UI re-render ◀── zustand subscription ◀── store.set({ doc, past }) ◀── snapshot
```

- Components dispatch commands; they never edit `doc` fields in place.
- `applyCommand` clones the doc, validates, mutates the clone, and returns it. The store snapshots
  the previous doc into `past` (bounded by `HISTORY_LIMIT`).
- The playback engine sits outside React: it reads the current doc through `getDoc()` on every frame
  and pushes time/playing state back into the store, which propagates to the views.
- Export instantiates a second, independent `PlaybackCore` bound to a frozen doc snapshot and an
  offscreen canvas.

## Undo/redo and transient gestures

History is a pair of whole-`Doc` snapshot stacks (`past`, `future`) capped at `HISTORY_LIMIT = 100`.
Committed commands push; undo/redo pop between the stacks. Drag gestures wrap the same machinery so
that one gesture equals one history entry.

```text
 Committed command                      Drag gesture (transient)
 ────────────────────                   ─────────────────────────────────────────
 UI: store.apply(cmd)                   UI: beginTransient()
        │                                       │
 applyCommand(doc, cmd)                 transientBase = clone(doc)
 = clone → validate → mutate                    │
        │                               each pointermove:
 set({ doc: next,                       UI: applyTransient(cmd)
      past: past + [oldDoc],              = applyCommand(doc, cmd)   ← no history push
      future: [] })                         invalid mid-drag states are
        │                                   swallowed to keep the gesture smooth
 any later apply()                              │
 clears `future`                       pointerup:
                                               │
 undo():                                commitTransient()
   past.pop() → doc,                      changed? past + [transientBase]
   doc → future[0]                        transientBase = null   (1 undo entry)
 redo():                                        │
   future.shift() → doc,                cancelTransient()
   doc → past.push                        doc = transientBase (discard changes)
```

Details worth knowing:

- `commitTransient()` compares the base and current docs by JSON equality; a click-without-drag
  pushes nothing.
- The transient flag is module-level (`isTransientActive()`), cleared _before_ the final `set()` so
  the autosave subscription observes a settled state and schedules the save. This ordering was a real
  bug source (fixed before the initial commit).
- `EditorShell` listens for `window` `pointerup` and `blur` and commits any dangling gesture, so
  history can never stay open after pointer capture is lost.
- `undo`/`redo` drop the selection when the selected clip does not exist in the restored doc
  (`normalizeSelections` filters dangling ids, so deleting selected clips never leaves ghosts).
- `replaceDoc` (project load, autosave restore) pushes the previous doc onto `past` too, so even
  loading a project is undoable.
- Placement plans are single batches: `planInsert` / `planOverwrite` return an `EditorCommand[]`
  (shifts, splits, trims, deletes) that the placement route appends the `addClip` / pair commands to
  and applies through `applyCommands` in ONE `store.apply`, so a drop's displacement and the placed
  clip share one undo entry. A refusal decides before `apply`, so it writes nothing at all.

## A/V link groups

A video that carries audio is placed as **two clips sharing one `linkId`**: the video part on a video
track and an `audioOnly` twin on an audio track. The group is the unit of editing until it is
unlinked.

- **Data.** `Clip.linkId` bonds the pair; `Clip.audioOnly` marks the sound-only twin;
  `MediaAsset.hasAudio` records whether the source has a decodable audio track (probed at import,
  with a waveform-peaks fallback for legacy saves).
- **No double audio.** `PlaybackCore.computeGain` sets the video part's embedded audio gain to 0
  while its linked twin exists (`hasLinkedAudioTwin`, which never applies to the carrier itself). The
  video element keeps playing to feed compositor frames. Unlinking unmasks the embedded audio.
  Deleting the twin while the video part remains hands the sound to the video part: its embedded
  audio becomes the clip's sound in both render paths (the shared `clipRendersAudio` predicate).
  Only a VIDEO part is shadowed: a separate audio clip merged into the group by a manual link has no
  embedded audio to hide and keeps its own sound, which the export mix already renders.
- **Missing carrier.** A twin whose media is gone still counts as the carrier
  (`hasLinkedAudioTwin` deliberately does not check the twin's playability), so the pair stays silent
  until the asset returns. Unmasking the video half instead would play its embedded audio, a
  different source whenever the group spans two assets, which the export mixer never renders; preview
  and export would stop agreeing. The rate predicate follows the same rule: `linkGroupChangesRate`
  tests carrier-ness on the whole group, so a missing carrier keeps the pair's rate semantics too.
- **Rate disagreement.** In an A/V pair (a group with an `audioOnly` carrier), any effective-rate
  disagreement among the group's A/V members (the carriers and the video-bearing parts) drops their
  audio in preview, export and ducking alike (`linkGroupChangesRate`); the identity seed and equal
  speeds keep it, and a solo clip always keeps its resampled audio. A clip whose own real ramp cannot
  render drops its own audio even outside a pair, and a manually linked group without a carrier keeps
  every member's own rate and audio.
- **Merged groups (3+ members).** `linkClips` merges whole groups, so a link group can hold more
  than a pair. Sound then follows MEMBERSHIP: while the group has ANY `audioOnly` member, every
  non-carrier video part is shadowed, every `audioOnly` member is a sound source, and a separately
  linked kind-audio clip keeps its own sound. The rate rule binds only the group's A/V members (the
  carriers and the video-bearing parts): one real ramp among them, or two of them with disagreeing
  effective rates, silences those members at once (preview, export plan/mix and ducking alike),
  while a kind-audio clip keeps its own resampled rate and sound and drops its own audio only when it
  carries a real ramp itself. No `audioOnly` member means a manual link, so there
  is no shadow and no rate lock: every member keeps its own rate and audio. Missing media does not
  change membership: an unplayable member still counts as a carrier but is skipped by the rate
  comparison.
- **Group operations.** Delete, split, duplicate, cut/copy/paste, and move all expand the selection
  through `resolveSelectionGroups` and run as ONE undoable batch. `splitClip` gives the right halves a
  single fresh `linkId`, so a split pair stays paired.
- **Manual linking.** `linkClips` bonds any 2+ non-text clips from ≥2 distinct groups; the first
  existing group id wins so unselected partners stay bonded. `Ctrl+L` unlinks when the selection is
  already linked, otherwise links it.

## Compound clips

A **compound clip** is a clip that carries `sequenceId` (and no `mediaId`, `text` or `audioOnly`) and
references a project-level `Sequence` (`Project.sequences`). Sequences live inside `Doc`, so compounds
are undoable, autosave and serialize. A sequence is SHARED: duplicating a container reuses the same
edit, which is what makes a compound a reusable unit rather than a group.

- **Identity.** Sequence, track and clip ids are globally unique (v4 enforces it). `findClip`/
  `findTrackIn` search the root and every sequence and report the owner; owner-scoped callers
  (`links.ts`, `sequence-ops.ts`, `tracks.ts`) stay inside one sequence.
- **Guards.** Creating a compound refuses a selection that spans sequences, a placement that would
  close a reference cycle, and nesting beyond `MAX_SEQUENCE_DEPTH` (8). The loader refuses the same
  malformed graphs (plus duplicate ids and incompatible compound fields) rather than trust them.
- **Compositing.** The referenced sequence composites into a transparent, depth-indexed scratch surface
  and that single surface is drawn with the container's opacity, transform, transition and grade (a
  GROUP composite, so overlapping children differ from a per-child fan-out). The preview compositor and
  the export planner share the rule; the export always starts from the project root.
- **Audio.** A compound's children mix into a container gain node that applies the container's gain,
  mute and volume curve once, in `PlaybackCore` (ancestor gains multiplied into each nested clip) and in
  the offline export mix (a container gain node per nesting level).
- **Navigation.** `activeSequencePath` (store-only, never in `Doc`) is the open sequence path; the
  timeline, selection, lane targeting and transport scope to it, and a breadcrumb jumps back to a parent.
  Project-level markers stay at the root; a compound clip's markers are container-local.

## Markers

A marker is a **point** in time with an optional name, one of eight colors and free-text notes. Two
scopes exist, both inside `Doc`, so both are undoable and both persist:

- **Sequence markers** live on `project.markers` in **timeline seconds**.
- **Clip markers** live on `clip.markers` in **SOURCE seconds**, the same basis as `Clip.inPoint`.
  `clipMarkerLocalTime` is the inverse of `sourceTimeAt` (speed, reverse and `timeScale`-ramp
  aware), so trimming, rate-stretching or reversing a clip keeps a marker on the same media frame. A marker whose source
  time falls outside the clip's visible span is **kept in the data but not rendered**; extending the
  clip brings it back. A split copies the whole list onto both halves (fresh ids on the right half, via `reIdMarkers`) and the per-half visibility filter decides which tabs show, so a cut never loses a cue.

The marker **selection** (`selectedMarker`) is store state, never part of the Doc: it is exclusive
with the clip selection, cleared by Escape, empty-space clicks and any clip-selection setter, and
normalized away by `apply`/`undo`/`redo` when its marker stops existing. `M` adds a marker (a clip
marker on the primary selected clip, clamped into its visible span, otherwise a sequence marker at
the playhead), `Shift+M`/`Ctrl+Shift+M` seek to the next/previous marker with no wrap, and Delete
prefers the selected marker over the clip selection. Markers are snap targets for clip drags and
trims in both directions (a dragged marker snaps to clips too), and export ignores them entirely.

## Timeline z-order

`tracks[0]` is the topmost compositing layer; the compositor draws last-to-first. Any array order is
render-legal.

- Conventional order is text → video → audio, applied by `addTrack` when no explicit position is
  given.
- `addTrack` with `atIndex` splices the track at an exact z-position and **skips** the convention
  sort — dropping media between tracks is explicit layering intent, so it wins.
- New tracks of a kind insert at the head of that kind's group (Premiere semantics: a newer `V2`
  stacks above `V1`).

## Audio graph

Built lazily by `PlaybackCore.ensureAudio()`; one graph serves preview and export. Element routing is
set up per clip on demand in `applyGain()`.

```text
HTMLVideoElement / HTMLAudioElement   (one per clip — ClipMediaPool)
        │
        ▼
MediaElementAudioSourceNode           (one per element per AudioContext)
        │
        ▼
GainNode  (per clip)                  gain = clip.gain × clip.muted × track.muted
        │                                    × crossfade alpha × (twin-shadowed ? 0 : 1)
        ▼
GainNode  (master)                    volume = preview master volume (0..1)
        └──▶ AudioContext.destination                  (speakers, preview)

Export does not tap this graph: it re-renders the mix in an `OfflineAudioContext`, so the preview
clock and the media element pool stay untouched while a render runs.
```

Fallbacks and edge cases:

- No `AudioContext` (or construction throws): the clock falls back to `performance.now()` and gain is
  applied via `element.volume`, clamped to 0..1 (so gain > 1 is only possible with Web Audio).
- Autoplay policy: `prepare()` creates/resumes the context and is called from user-gesture call
  chains (transport click, export start).
- The master volume ramp uses `setTargetAtTime` with a 20 ms time constant to avoid zipper noise.

## The crossfade model

Two transition types exist: `crossfade` and `dipToBlack` (0.8.2 adds the dip). The model is asymmetric and deliberately
render-time-tolerant:

1. **The transition lives on the outgoing clip.** `clipA.transitionOut = { type: 'crossfade' | 'dipToBlack', duration }`
   means "dissolve (or dip through black) from A into whatever follows A on the same track." `addTransition`
   takes an optional `transitionType` defaulting to `crossfade`, and a duration-only re-dispatch keeps the
   clip's existing type instead of resetting it.
2. **Overlap is real, not virtual.** `addTransition` pulls the next clip left so its head overlaps A's
   tail by exactly the (clamped) duration: `b.start = a.start + a.duration - duration`. The duration is
   clamped to `TRANSITION_MIN..TRANSITION_MAX` and to `maxTransitionDuration(a, b, aEnd)`.
3. **The effective duration is clamped at render time.** `getTransitionSpan(a, b)` computes
   `overlap = a.end - b.start` and uses `min(requested, overlap)`; if the overlap disappears there is
   no transition, and later moves/trims shorten it instead of breaking it.
4. **Rendering.** Over `[b.start, b.start + effectiveDuration]`, `transitionAlphas(span, t)` yields
   linear complementary alphas for a crossfade (`aAlpha = 1 - p`, `bAlpha = p`); both are fully opaque outside the span.
   For a dip the outgoing clip fades 1 → 0 over the first half and the incoming clip 0 → 1 over the
   second half, so both alphas are exactly 0 at the midpoint: the pair contributes nothing and lower tracks
   show through fully (track-pair black, not program black; at a crossfade midpoint they show through
   the two half layers instead).
5. **Audio follows the same math for both types.** `computeGain` multiplies the outgoing gain by `1 - p` and the
   incoming gain by `p` inside the same span, so the video transition and audio ramp stay in sync; the dip
   is video-only by design.
6. **`removeTransition` only clears the flag.** The next clip keeps its overlap; visually the later clip
   wins during the overlap, which keeps undo semantics predictable.

Splitting interacts correctly: `splitClip` moves the outgoing clip's `transitionOut` to the right-hand
fragment and clears it on the left fragment.

## Invariants

Rules the codebase relies on; new code must preserve them.

1. **Commands never mutate the input doc.** `applyCommand`/`applyCommands` `structuredClone` first;
   every mutation happens on the clone.
2. **All times are seconds (floats).** No frames, no milliseconds anywhere in the model; frame
   conversion exists only in `time.ts` helpers.
3. **Timeline position is `start + duration`; source position is `inPoint`.** For video/audio,
   `inPoint >= 0` and `inPoint + duration <= asset.duration`; images and text are unbounded.
4. **`tracks[0]` is the topmost compositing layer.** The compositor draws last-to-first; `addTrack`
   re-sorts to text → video → audio unless an explicit `atIndex` is given.
5. **Clips keep their `mediaId` after asset removal.** Missing media is a render/UI concern
   (`missing: true`, relink flow), never a silent clip edit.
6. **Object URLs are never serialized.** `serializeDoc` strips `url`; `deserializeDoc` hydrates assets
   with `url: ''` and `missing: true`.
7. **`MIN_CLIP_DURATION` (0.1 s) is the floor.** `addClip`/`trimClip` reject shorter durations;
   `deserializeDoc` clamps hydrated clips to at least 0.05 s rather than dropping data.
8. **Splits need headroom.** `splitClip` requires `at` to be at least `MIN_SPLIT_HEADROOM` (0.1 s)
   inside both edges.
9. **Gain is linear and clamped** to `GAIN_MIN..GAIN_MAX` (0..2); **opacity is clamped** to
   `OPACITY_MIN..OPACITY_MAX` (0..1) and omitted at 1 to keep saved files clean.
10. **History is whole-doc snapshots, capped at `HISTORY_LIMIT` (100).** Anything undoable must live
    inside `Doc`; playhead, zoom, selection, snap line and track targeting are deliberately
    non-undoable.
11. **At most one transient gesture may be active.** `beginTransient` overwrites `transientBase`;
    window-level `pointerup`/`blur` guarantee the gesture is committed or cancelled. A gesture that
    starts while another already owns the base is refused, and the check is made against the store's
    shared flag rather than a component-local one — the clip drag's own ref cannot see a drag running
    on a different clip.
12. **The last track cannot be removed** (`removeTrack` throws when one track remains).
13. **Track compatibility is enforced at the command layer**: video/image on `video` tracks, audio on
    `audio` tracks, text clips on `text` tracks (`clipFitsTrack`). `audioOnly` twins of video assets
    are the exception that admits them to `audio` tracks.
14. **A link group edits as one unit.** Every group operation resolves the union of link groups and
    commits a single history entry; `splitClip` re-pairs right halves with a fresh `linkId`.
15. **The store is the single source of truth.** The engine reads via `getDoc()` and never holds a
    stale doc reference; export binds to an explicit doc snapshot on purpose.
16. **Serialization validates before trusting.** `deserializeDoc` coerces unknown fields to defaults,
    drops non-finite numbers, and raises `SerializationError` for a wrong `version` or missing
    `project.tracks` rather than producing a half-broken doc.
17. **A track an edit empties is removed with that edit.** `pruneEmptiedTracks` (applied by the store
    on committed edits, inside the same history entry — so one undo restores both the clip and the
    lane) drops only the tracks whose LAST clip this edit took away. A track that was already empty
    is kept, which is what keeps "add an empty layer, then fill it" working, and at least one track
    always survives. Transient drag frames are exempt — the lane a drag is leaving must outlive the
    gesture that empties it.
18. **Marker times follow their scope.** `Project.markers` are timeline seconds; `Clip.markers` are
    SOURCE seconds (the `inPoint` basis), and the conversion lives only in `markers.ts`. A clip
    marker outside the clip's visible source span is kept, not deleted, and the marker selection is
    store state (invariant 10), never serialized.
