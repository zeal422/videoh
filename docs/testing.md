How the editor is verified. Sibling docs: [docs index](README.md) ·
[architecture.md](architecture.md) · [structure.md](structure.md) · [flows.md](flows.md) ·
[design-system.md](design-system.md) · [deployment.md](deployment.md).

## Commands

```bash
bun run test            # vitest run — single pass (NOT bare `bun test`)
bun run test:watch      # watch mode
bun run test:coverage   # v8 coverage with enforced thresholds
bun run battery         # scripted 70-step UI battery against a live server
bun run check           # full gate: format:check → lint → typecheck → test → build
```

> Run the suite with `bun run test`, not `bun test`. Bun's own runner ignores `vitest.config.ts`, so
> the `@/` alias, the Node environment, and the coverage settings would not apply.

## Setup

`vitest.config.ts` runs everything in a plain **Node** environment (`environment: 'node'`), maps `@`
to `src`, and includes `src/**/*.test.ts` and `src/**/*.test.tsx`. Coverage is collected from the
Node-testable state modules only: `commands`, `trim`, `ripple-trim`, `slip`, `sequence-ops`, `ease-segment`, `effects`, `chroma-key`, `factories`, `snap`, `srt`, `vtt`, `time`, `transition`, `tracks`, `timeline-scroll`,
`marquee`, `markers`, `offline`, `proxy`, `serialization`, `project-validation`, `store`, `persistence`, `workspace`, `theme`, `menus`, `bezier`, `color`,
`lut`, `frame-blend`, `filmstrip`, `clip-gesture`, `volume-automation`, `pen`, `denoise`, `releases`, `seo`, with thresholds **70 %
statements / 60 % branches / 75 % functions / 70 % lines**. The browser-bound `analytics.ts` is tested in jsdom and is not in the Node coverage set.

The pure state core is deliberately browser-free so it runs in Node. Browser APIs live in `media/`,
`playback/`, and `export/`; the browser-bound `persistence.ts` and `project-io.ts` helpers are
exercised with mocked storage or File inputs, while their DOM-only paths are covered by the battery.
Browser-path modules are tested through the mocked harness or by static wiring assertions.

## Dev audit state

After the 0.19.5 Bun 1.4.4 tooling update, `bun audit` reports no vulnerabilities
(572 packages checked), and `bun audit --prod` was already clean. The last 15
dev-only entries cleared through within-range `bun audit fix` bumps for
`brace-expansion`, `minimatch`, and `picomatch`, plus one scoped override for
the TypeScript ESTree chain: `@typescript-eslint/typescript-estree>minimatch`
at `^11.0.5`. That scoped rule writes `bun.lock` as `lockfileVersion: 3`,
which Bun older than 1.4 cannot read, so `vercel.json` carries an explicit
install (`installCommand`) until a preview proves the build Bun.

Timing medians on the same dependency graph, warm cache: `bun install
--frozen-lockfile` 24 ms to 21 ms, and one single-file vitest run 822 ms to
823 ms. The test run shows no measurable change, and the install difference is
within noise.

## Track solo and lock (0.14.0)

- The typed `LOCK_RULES` map in `commands.ts` is the completeness lock: TypeScript fails the build when
  a command lacks a decision. `track-controls.test.ts` proves every blocked command refuses with the
  lane named, and every exempt command still applies on a fully locked doc.
- Store guarantees are tested directly: a refused `apply`, `applyTransient`, or batch leaves the doc
  byte-identical and pushes no history entry, and `lockNotice` carries the message the shell shows.
- Solo audibility is one helper (`audibleTrackIds`). The preview mixer, `planAudioFrame` and the MP4
  `renderAudioMix` run the same matrix: no solo, one and two solos, solo plus mute, a solo video's
  embedded audio, independent parent/child solo in a compound, and a container on a soloed parent lane.
- Serialization reads absent flags as false, drops hostile values and a solo flag on a non-audio lane,
  and loads v1 to v3 files unchanged (no schema bump).

## Ripple trim and slip (0.15.0)

- `ripple-trim.test.ts` is the primary proof: head and tail trims, anchored starts, one shared end
  delta, speed 0.5/2 and reversed clips, a time-remap fallback, markers/keyframes/link ids carried,
  a transition overlap preserved, an unexplained overlap refused, a left shift crossing 0 refused,
  locked lanes and later locked partners, and the same-track link exception asserted as a recorded
  divergence.
- `slip.test.ts` owns the planner and the `setClipInPoint` command: source-window bounds by
  `duration * speed`, clamping and no-op, reversed windows, image/text/compound/time-remap refusals,
  the shared linked-pair delta, mixed-window groups refused, start and duration untouched, and every
  member lane's lock respected.
- `editing-tools-ui.test.tsx` routes the real pointer handlers: the two toolbar buttons and pressed
  state, V/C/B/Y/Escape and Ctrl+Y, ripple head and tail drags with one undo, the Alt rate-stretch
  shift, slip with `data-in-point` and a readout, returning either tool to its origin with no
  history, the body-versus-edge matrix, pointercancel and a foreign commit, image and locked-lane
  refusals that write nothing, and a live gesture that Escape cannot switch out from under.
- The store tests cover `resetTransient`: it restores the base, keeps the gesture open and its token
  stable, and a later frame still commits one history entry.
- The `trimClip` gate has a red-first regression: a start-anchored head trim at speed 2 kept its
  old in point before the constant-rate rebase was gated on the start actually moving.

## Keyframe Pen (0.16.0)

- `pen.test.ts` is the pure proof: the structural property rule (audio lane or `audioOnly` reads
  volume; video, image, text, compound, and a solo video read opacity), clipped sampling through
  `animatedValue`, the dB and 0..1 display maps, add with one-frame replacement, sorted insertion,
  removal, nudge clamping and crossing, hostile times/values/fps, and non-mutation.
- `volume-envelope.render.test.tsx` proves the generalized envelope: the existing volume behavior,
  opacity visibility (only keyframes or the Pen target), a Pen click adding a point at the
  interpolated value, opacity drag/remove/nudge/cancel/lock, the dots-only volume overlay on a solo
  video, and the opacity click that leaves the clip position untouched.
- `editing-tools-ui.test.tsx` routes the real timeline: the Pen button and pressed state,
  P/V/C/B/Y/Escape, the body-versus-edge no-op matrix, volume and opacity click-add with one undo,
  a dot drag, Shift selection, the live-gesture Escape rule with the keyboard hook mounted, and a
  locked-lane refusal that writes nothing.
- `volume-envelope-ui.test.ts` keeps the static layering locks: the opacity instance renders before
  the volume instance, only dots and the line hit path take pointer events, the white curve never
  uses the selection rose, the trim inset and z-order hold, and every edit goes through
  `setClipKeyframes`.
- Coverage adds `src/lib/editor/pen.ts` to the include list; it is at 100% statements, 100%
  functions, 100% lines, and 98.18% branches.

## Mocked browser harness

`src/lib/editor/__tests__/mocks/browser-mocks.ts` installs deterministic stand-ins for the browser
APIs the engine depends on (the MediaRecorder fakes left with the retired WebM exporter in 0.5.0):

- `FakeAudioContext` with a controllable clock and a recorded gain graph (reverse edges included), plus biquad / compressor / stereo-panner nodes that record the parameters the shaping chain sets
- `HTMLMediaElement` state machines (play/pause/paused/currentTime + `seeked` dispatch)
- a `requestVideoFrameCallback` queue with the exported `presentFrame(el, mediaTime)`: the engine's frame-blend weight reads the media timestamp of the frame each element PRESENTED, which jsdom never does on its own, so a test presents the frames a decoder would and asserts the weight the pair produces
- a recording fake `CanvasRenderingContext2D` proxy (every op the draws use is listed in it: an unrecorded method resolves to undefined and would silently no-op, so `putImageData` is there for the 3D LUT pass and the additive blend composite is readable as a call trace)
- `FakeMediaStream` + `FakeMediaStreamAudioDestinationNode` for the audio graph
- `ResizeObserver` no-op (Radix primitives measure via it and jsdom has none)
- a manual `requestAnimationFrame` pump, plus `installBrowserMocks()` and the harness's `uninstall()`

Suite names do not encode harness use: `.mocked.test.ts` marks the engine-level tests, while UI and
utility suites use `.test.ts(x)` and may install the same mocks. This harness has already paid for
itself: it caught a real export-cancel deadlock (the recorder kept recording and the poll interval
leaked) that the browser tests missed. See the entry in [CHANGELOG.md](../CHANGELOG.md).

## Static wiring locks

Some guarantees are about code shape rather than runtime behavior — CSS z-index order, a Tailwind
class contract (a `@container` query where a `sm:` viewport query would clip the transport), or a
component being mounted in a flex container. Those are asserted by reading the source or the
component's rendered output directly.
Static-lock suites include `compositing-ui.test.ts`, `timeline-layers.test.ts`,
`preview-layout.test.ts`, `markers-timeline-ui.test.tsx`, `text-presets-ui.render.test.tsx`,
`menubar.test.tsx`, `public-surface.test.ts`, `license.test.ts`, `volume-envelope-ui.test.ts`, and
`theme.test.ts`; each assertion
carries a comment explaining the regression it prevents.
`theme.test.ts` also carries the pure preference and palette contrast locks, which use the same
source-read approach.

## Conventions

- **A regression test must fail on the unfixed code before it counts as proof.** Write it against the
  broken behavior first, watch it fail, then fix.
- Unit tests build docs through the `factories` constructors; commands validate and throw
  `EditorCommandError` on bad input.
- Keep the state core testable in Node — do not import browser globals into `src/lib/editor/` outside
  `media/`, `playback/`, and `export/`.
- When you add a test file or change the totals, update this table and the test-count references in
  the [README](../README.md).

## End-to-end battery

`e2e/battery.sh` drives the real UI through every product feature in 70 steps (public hero and
editor link, then welcome-modal dismissal, fixture import from `e2e/fixtures/` through the media bin
input plus a real non-bundled file upload, quick-add, a keyboard-only
insert of a marked source range at the playhead (bin selection, `I`/`O`, `,`, one Ctrl+Z), marquee box
selection, the welcome modal (Help > What's new opens it; a recorded version stays silent on
reload), markers (sequence add/drag/navigate/delete + clip add/edit/delete), playback +
compositing, split/undo/redo, trim, rate stretch on a relinked-shorter asset (the over-consuming
window recovers, with the clamped span's rate on the badge), duplicate, copy/paste, unlink, ripple
delete, ripple trim (the later clip shifts while a linked audio twin on another track stays), slip
on a standalone audio clip (the source in point moves while start and duration do not), the Pen
(a curve click adds one opacity point, one undo removes it, and the clip geometry is unchanged),
crossfade, text, captions (an SRT import creating timed flagged clips, then an
export downloading the cues back in start order with the equal-start tiebreak intact,
plus a VTT download of the same cue list),
audio plus the reverse switch and a seeded time-remapping curve (the reversed-clip trim's frame
invariance is proved in pixels), the scope meters (the waveform and vectorscope canvases must paint
real pixels, and the waveform must tile the full meter canvas on a square project), a .cube import
grading the monitor through the Inspector's real file input (the fixture makes every graded pixel
pure red, so the green channel must collapse while red stays, and one Ctrl+Z must return the row to
None), the monitor's blend parity with the export plan (a 0.25x clip is stepped through
12 output frames while an in-page decoder builds each frame's plan pair from the same file, and
the canvases must agree pixel for pixel), menus, panels (close Media and the Program Monitor, hide
the upper row and close the bottom row with measured reclaim, close all six and reopen one from
Window, reset from all hidden and from a reduced layout with default-share geometry, captions
and the vertical timeline bound at their caps and floors with persisted values, and double-click
handles with the solo guard), autosave/save plus a save-to-file capture, File > New and reopening the
saved `.veproj.json`, export at 1080p (the exported MP4's own stream layout: the warm render must
carry an audio track while an audible clip exists, and after `mute_all_audio` mutes every
audio-capable clip the cool render must carry none, read from the file's moov handler types by
`export_track_kinds`, and a third render must show the same green-collapse signature after the cube
is assigned, then undo the batch), settings, and a zero-console-error check). It was built for
A/B verification of the mocked harness against real browser APIs and still runs as a smoke test:

```bash
bun run battery                                # starts a dev server if :3000 is free, then stops it
DETACH=1 bun run battery                       # detached, the verdict lands in the log
OUT=results-a.txt SESSION=ab-a bun run battery # a named run, for A/B diffing
```

`e2e/run-battery.sh` is the runner: it starts a dev server only when the DEFAULT port
(`http://localhost:3000`) answers no HTTP and nothing is accepting TCP there, closes its
`agent-browser` session on every exit path, and stops only a server it started. An HTTP probe of `000` is not taken as "free": a server mid-start can
time out, so the port is checked for any TCP listener and a second dev server is refused, and a
started server must still be alive before it can be declared ready. It needs `agent-browser` on
`PATH`. Any other `BASE_URL` must already be serving: the runner reuses that server and refuses to
start one on a non-default port (`DETACH=1`, `OUT`, `SESSION`, `BATTERY_SH`, `LOG`, `KEEP_DEV` and
`KEEP_SESSION` are all read from the environment; the script header lists them).

Two details matter when an agent drives it. First, the verdict is strict: it exits 0 only when every
`step` line in `e2e/battery.sh` produced a `PASS`, so a `FAIL` or an incomplete run cannot be reported
as green. A run killed halfway leaves a partial `PASS` list behind, which is why the runner counts the
results against the registered steps and fails with `INCOMPLETE` when they disagree, and why it
truncates the results file before the battery starts. Second, use `DETACH=1` when the launching
harness may clean up background children: it re-execs under `setsid`, so the run owns its own session
and a session ending no longer takes the dev server and the battery with it. The launcher prints the
run's log path (a unique `/tmp/run-battery-<date>-<pid>.log` unless `LOG` says otherwise; a detached
run's default `OUT` and `SESSION` carry the same per-run id, so two detached runs cannot overwrite
one results file or close each other's browser, and an explicit value is preserved) and exits 0
to mean the child started, NOT that the run passed; it refuses to launch at all (exit 9) when that
log cannot be written. The run's outcome is the terminal
`BATTERY_EXIT=<code>` line every exit path writes to that log, so a detached caller polls the log for
it (0 = every step passed). A failed step records `FAIL` and the run continues to a full
70-result verdict; no step aborts the script (the e06 dirty-timeline guard used to `exit 1`
and turned one effects flake into an INCOMPLETE run, and now returns 1 like every other
guard). The raw script still runs
on its own (`BASE_URL=... OUT=results.txt bash e2e/battery.sh`); the runner just adds the lifecycle and
the guard. Results are written as `PASS`/`FAIL` lines so two runs can be diffed. `results*.txt` is
gitignored.

Clicks are dispatched at an element's screen coordinates, and both the Inspector and the timeline are
scroll areas shorter than their content. A control can therefore be listed in the a11y snapshot and
still be below the fold, where a blind click lands on whatever is painted at that point (the Timeline
header, or the app footer) instead of the control — which is how `f03 crossfade` and both `f05` audio
steps used to fail on a short viewport. Every step scrolls its target into view first (`insp()` for
Inspector controls, `click_clip()` / `delete_clip()` for clips), which keeps results independent of the
window height. **When you add a step that clicks or fills an element, scroll it into view first.**
Project-size edits read the Inspector-scoped spinbuttons (`insp_spinrefs`) because the hidden export
dialog also contributes numeric inputs, and the relink step scrolls its media card into view and
requires a new clip before it saves the project.

### Two trees (A/B)

The battery was built to compare two checkouts: one run per tree into its own results file, then diff.
Different `SESSION` names keep the two runs from sharing a browser, and the second tree's server has to
be started by hand because its port is not the default one:

```bash
# tree A (this checkout): the runner starts a dev server on the default port
OUT=results-a.txt SESSION=ab-a bun run battery

# tree B (another checkout), from inside that tree: start its server, then run the battery
bunx next dev -p 3100
BASE_URL=http://localhost:3100 OUT=results-b.txt SESSION=ab-b bun run battery

diff results-a.txt <tree-b>/results-b.txt
```
