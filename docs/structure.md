Everything is committed; there is no backend, no database, and no server-only code. The editor runs
entirely in the browser (object URLs, canvas, Web Audio, MediaRecorder).

## `src/lib/gate.ts` — the access gate primitives

Pure session/throttle crypto (HMAC-SHA256 via node:crypto, constant-time compares): sign/verify the
24 h session cookie under a key derived from `GATE_SECRET` + `GATE_PASSWORD` (`sessionKey()`), the
failure-counter cookie, and the delay ramp. `gate-env.ts` resolves and validates the two env
materials (secret required in production, dev warns and falls back). Unit-tested in `gate.test.ts`;
`src/proxy.ts` (Next 16 middleware) and `src/app/api/gate-login/route.ts` wire it to cookies. See
[deployment.md](deployment.md#access-gate).

## `src/lib/editor/` — the editor core

The heart of the app. Everything here is plain TypeScript with no React dependency except the zustand
stores. This is the layer that unit tests target.

```text

├── types.ts              # Doc / Project / Track / Clip / MediaAsset / TextStyle
├── constants.ts          # all tuning constants and limits
├── factories.ts          # uid + create* constructors, finders, compatibility checks
├── time.ts               # clamp, formatTime/Timecode, frame stepping, rulerStep
├── commands.ts           # the 22 EditorCommand variants + applyCommand(s)
├── snap.ts               # snap-point computation and application
├── transition.ts         # crossfade span + alpha math
├── links.ts              # multi-selection / A/V link-group helpers
├── clipboard.ts          # copy / cut / paste (module memory, outside undo)
├── actions.ts            # multi-command UI actions (add media/text, group ops, ripple delete)
├── store.ts              # zustand store: doc, history, transients, selection, playhead, zoom
├── serialization.ts      # .veproj.json v1: serialize / parse / hydrate

├── workspace.ts          # panel layout state (pure)

├── menus.ts              # menu bar model (pure)
```

`src/lib/utils.ts` holds the shadcn `cn()` class-merge helper.

## Conventions

- Tests are colocated under `src/lib/editor/__tests__/` and named `*.test.ts`. Component "wiring"
  behavior is verified by static-source tests rather than a DOM renderer (see
  [testing.md](testing.md)).
- The state core must stay browser-free so it can run in Vitest's Node environment; browser APIs are
  isolated to `media/`, `playback/`, and `export/`.
- Nothing under `src/lib/editor/` imports from `src/components/`.
